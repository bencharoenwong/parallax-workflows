**What changed:** the shared render-gate invocation documented in
`skills/_parallax/parallax-conventions.md` §10.3, and reproduced in 22
`skills/parallax-*/SKILL.md` files (plus their generated `plugin/` mirrors),
moved from a form that wrote the drafted report to a `mktemp`-created file,
`cat`-redirected the heredoc into it, invoked `render_gate.py` with the file
reopened on stdin, and removed the file afterward, to a form that feeds the
quoted heredoc directly to `render_gate.py`'s stdin with no named temp file
at all. `render_gate.py` itself is untouched (confirmed via diff — zero
lines changed in that file). Also touched: `evals/concierge_journeys.sh`
(backgrounds `caffeinate` during a live run), `evals/README.md` and
`evals/tasks/concierge/journeys.jsonl` (documentation/fixture-text updates
describing the same change), and a new regression test,
`skills/_parallax/test_render_gate.py::test_gate_commands_use_stdin_heredoc_without_expansion`,
that asserts every one of the 22 SKILL.md files plus the conventions doc uses
exactly the new stdin form and that no file contains a leftover reference to
the old named-temp-file variable.

**Why:** `evals/README.md`'s own updated text states the root cause plainly —
Claude Code's own command-permission check denies any Bash command containing
a shell-expansion sequence, sandboxed or not, independent of this repo's own
sandbox config. The old form's first line contained exactly such a sequence
(a command substitution assigned to a shell variable), so every concierge
journey that reached the render-gate step failed its first gate attempt
before this fix, regardless of this repo's code. This is a functional fix
with a security-relevant side effect, reviewed below under SEC-10 and
SEC-12.

**Targeted probes run today, beyond the standard sweep:**

- **Shell-expansion / injection safety of the new heredoc form.** Both the
  old and new forms use the same quoted heredoc delimiter
  (`<<'REPORT'`), which was already correct in the old form and remains
  correct in the new one — a quoted delimiter disables all shell
  parameter/command/arithmetic expansion inside the body in both bash and
  zsh, so report text containing `$`, backticks, or `!` was never
  interpreted by the shell either before or after this change. No
  regression here; the change is to what surrounds the heredoc (a named
  temp file vs. direct stdin), not to the heredoc's own quoting.
- **Delimiter-collision property, unchanged.** In both the old and new
  forms, a report body line that is exactly the literal word used as the
  heredoc delimiter would terminate the heredoc early. This was already
  true of the pre-existing quoted-heredoc form and is not introduced or
  worsened by this change; not a new finding.
- **Disk exposure of report content — the actual improvement, stated
  precisely.** The claim "the report never touches disk" would overstate
  this: on this platform, a shell's own heredoc implementation may still
  spool the body through a short-lived, unlinked-on-open temporary file
  or a pipe internal to the shell, in both the old and new forms alike.
  What changed is the **named, explicit** `mktemp` file that the old form
  created, left briefly resolvable by path under `TMPDIR` or `/tmp`, and
  relied on an explicit `rm -f` to remove — a file that would persist
  indefinitely if the process died between creation and cleanup (e.g. an
  interrupted run, a crash, a `kill` from the host). The new form has no
  such named, path-addressable file: there is nothing left on disk under
  a discoverable name if the process is interrupted, and nothing for the
  skill to clean up or forget to clean up. Net effect: strictly less
  operator-visible residue risk for report content (which may include
  client holdings and portfolio detail) in a shared or multi-user
  `/tmp`, not a change in whether bytes transiently exist in kernel
  buffers. Not a Critical finding either way — the old form was never a
  FAIL-level issue, since each temp file used `mktemp`'s random suffix
  (not a predictable/fixed path) — but worth recording as a real,
  if secondary, hardening from this change.
- **Host-transcript logging, unchanged.** Both the old and new forms pass
  the complete report as literal text inside the Bash command string that
  the orchestrating host executes and logs. Whatever retention policy
  applies to Claude Code's own command transcript applied equally before
  and after this change; this PR does not add or remove an exposure here.
- **Consistency of the 22-file rollout.** Grepped the full `skills/` and
  `plugin/` trees for the old form's temp-file variable name and for
  `mktemp` generally: the only remaining `mktemp` usages are in
  `skills/_parallax/client-policy/policy-loader.md` (a documented,
  unrelated use — writing RM-supplied client-policy YAML/JSON to a private
  randomized path before invoking a separate helper, pre-existing and out
  of scope for this change) and in genuinely unrelated test/script files
  (`build-skills.sh`, `install_git_hooks.sh`, several `test_*.py` files
  that exercise their own temp fixtures). No stray copy of the old
  render-gate temp-file form survives anywhere in either tree. The new
  regression test enforces this going forward (asserts the count of gate
  command occurrences equals the count of correctly-shaped stdin-heredoc
  blocks, and that no leftover temp-file-variable reference exists, across
  all 22 `SKILL.md` files plus the conventions doc).
- **`evals/concierge_journeys.sh`'s new `caffeinate -i -w $$ &`.** Guarded
  by `command -v caffeinate` (macOS-only, degrades to a no-op elsewhere),
  only invoked when not in dry-run mode, waits on the script's own PID so
  it exits when the runner does, and affects only the local machine's idle
  sleep behavior during a live, credit-billing eval run. No network effect,

- **`evals/tasks/concierge/journeys.jsonl`'s one-line change** (J4's
