## OWASP Findings Detail (supporting SEC-12) — in-scope delta only

**A05 Security Misconfiguration — `run-gate-tests.sh` offline-mode guard
(fixed within this delta, `4b908f1`):**

- **The bug the fix closes.** Before this delta, the offline branch set
  `PARALLAX_E2E_LIVE=0`, `PARALLAX_E2E_SPEND=0`, `PARALLAX_S1_INTEGRATION=0`
  as a "defense in depth" guard meant to force live/spend/integration paths
  off regardless of what an operator's shell had inherited. The common
  Python idiom for reading these flags is `if os.environ.get(FLAG):`, under
  which the string `"0"` is truthy (any non-empty string is) — so the
  literal value this script set was exactly the value that would have
  *enabled* the paths the comment says it suppresses, in any code that
  used that idiom. This audit could not find a live consumer of these three
  flags in the current in-scope diff (no code path reading them was part of
  this delta), so I could not confirm the bug was ever actually reachable
  in the codebase as it stands, but the shell script's own stated intent
  was defeated by its own literal value — a genuine defense-in-depth bug
  regardless of whether a consumer currently exists.
- **The fix.** The three assignments now export the empty string
  (`FLAG=`) rather than `0`. Empty string is falsy under both the
  `if os.environ.get(FLAG):` idiom and an explicit `== "1"` comparison, and
  it also beats plain `unset`, which would expose a
  `os.environ.get(FLAG, "1")` default-to-enabled gotcha in any future
  consumer that defaults on. The inline comment added alongside the fix
  documents this reasoning for future maintainers.
  - **Verdict:** fixed correctly, verified by direct reasoning about the
    three idioms a consumer could plausibly use; not scored as an open
    finding since the current tracked state is correct. Recorded here
    because the task asked for delta findings, and this is the one place
    this delta changed a security-relevant guard's actual value (as
    opposed to adding validation, wrapping an exception, or removing dead
    code).

**A08 Software and Data Integrity — `judge.py` view-reload wrapping (new
this delta, `4b908f1`):**

- `_assert_view_unchanged` previously called `phase_0_load_view` unguarded;
  if the active view directory had been cleared, corrupted, or had its audit
  chain broken by a concurrent operator action between the judge's read and
  its post-run reload, the raw `FileNotFoundError` or `AuditChainError`
  would propagate out of the function — contradicting the documented
  contract that callers catch `ViewChangedMidRun`/`ViewChangedDuringJudge`
  for "the view moved out from under me" cases, and potentially reporting
  a report against a view that no longer exists as if judging had failed
  for an unrelated reason.
- The fix wraps the reload in `try/except Exception`, re-raising as
  `ViewChangedDuringJudge` with a message naming the underlying exception via
  `from exc` (chained, not swallowed) and instructing the operator to
  re-run the judge. Confirmed by reading the two new parametrized tests
  (`wipe="view.yaml"`, `wipe="audit.jsonl"`), both of which assert the
  documented exception type and that no audit row was appended.
- Same threat model as the prior audit's assessment of the sibling
  `ViewChangedMidRun` guard in `maker.py`: this repo has no privilege
  boundary between the code and the operator invoking it, so this protects
  against benign concurrent-writer races, not an adversarial caller — same
  reasoning, not re-derived here as a new risk class.

**A03 Injection / input-handling — `infra_failure.py` auth-scan scoping
(this delta, `4b908f1`):**

- This is a grading-accuracy fix in an offline eval-transcript parser (reads
  already-completed, on-disk transcript files; not a request-handling
  surface). Before this delta, the 401-detection regex ran against the
  entire raw transcript line, so a Parallax tool response that legitimately
  quotes an HTTP status-code table (documentation-style content) could
  false-positive as the harness's own connector authentication failure and
  silently shrink the graded-run aggregate. The fix scans each JSON event,
  strips any `tool_result` content blocks before matching, and falls back
  to scanning the raw line verbatim only when the line does not parse as a
  JSON object (hand-written fixtures) — confirmed by reading
  `_without_tool_results`/`_has_auth_failure` and the two new tests
  (a 401 inside a tool result no longer matches; a 401 elsewhere in the same
  event still does). No `eval`/`exec`, no dynamic code path from transcript
  content, unchanged from the prior audit's assessment of this file.

**Correctness fix, no security implication — `web_pdf.py`'s
`_open_public_url` bare-string wrapping (this delta, `4b908f1`):**

- Before this delta, `_open_public_url` accepted a bare `str` in its type
  contract (a ternary computed `requested_url` from `str(request)` when the
  argument had no `full_url` attribute) but then unconditionally executed
  `request._parallax_pinned_ips = pinned_ips` a few lines later — which
  raises `AttributeError` on an immutable `str`. This was dead/broken code:
  every current call site in this repo passes an already-constructed
  `Request` object, never a bare string, so the latent crash was never
  reachable in practice. The fix wraps a bare string into a `Request`
  (with the same `User-Agent` header used elsewhere in this file) before
  proceeding, so the function's stated contract now actually works if a
  future caller passes a plain URL string.
- **Security-relevant question this fix raises, checked directly:** does
  the wrapped path still run the full destination-validation policy? Yes —
  `requested_url = request.full_url` is read from the now-wrapped `Request`,
  `_resolve_public_url(requested_url)` runs exactly as it does for the
  existing `Request`-object call sites, and the pinned IPs are stored
  before `_network_open` is called. No validation is skipped or weakened
  for the newly-accepted input shape. Confirmed by reading the function in
  full and by the new `test_plain_url_string_is_wrapped_before_pinning`
  test, which asserts both the pinned-IP value and that the opener received
  the expected `full_url`.

**Confirmed non-issue — `stress.py` dead-branch removal (this delta,
`52f4e6a`):**

- The removed branch (`if response.get("success") is True: return "ok" ...
  else: return "UNREACHABLE", "unrecognized response shape"`) was
  genuinely unreachable, not a fail-open weakening of a real check. Traced
  the call order directly: `classify_mcp_meta_state` first calls the shared
  `mcp_meta.shape_unreachable_reason(response)` helper, which already
  returns a non-`None` reason (triggering the earlier `UNREACHABLE` return)
  for every shape other than `success is False`, a non-`None` `error`, or
  `success is True` — the three cases `classify_mcp_meta_state` itself
  already exhausts before reaching the removed line. By the time execution
  reached the deleted branch, `response.get("success") is True` was always
  true; the `else` arm could never execute. Confirmed by reading
  `shape_unreachable_reason` in full, not merely by the passing test suite.
