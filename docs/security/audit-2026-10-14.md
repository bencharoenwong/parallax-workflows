## Security-relevant changes since `audit-2026-10-11.md`

**House-view commit path (`skills/_parallax/house-view/view_commit.py`,
`audit_chain.py`; `skills/parallax-make-house-view/maker.py`).** All of #167
lands in this one module plus its two
callers. Confirmed by direct code read against the current tree:

- `maker.py` routes every save through `view_commit.commit_view_locked`
  (`maker.py:741`), not a separate write path — `grep -n "view_commit\."
  skills/parallax-make-house-view/maker.py` shows no competing writer.
- A staged path-ref read (`{"path": ...}` in a commit plan) is bounded to a
  single declared `--staging-dir`, resolved once via `.resolve()` so a `..`
  traversal or an out-of-directory symlink is rejected before any read
  (`resolve_staging_dir`, `:799`), then re-opened through a directory file
  descriptor with `O_NOFOLLOW` so a symlink swapped in after the resolve-time
  check still fails closed, `fstat`-checked for regular-file type, `st_nlink
  == 1`, and a 16 MiB cap, all on the same descriptor the bytes are read from
  (`_read_staged_file`, `:886`).
- `commit_view_locked` requires a **live** `TransactionToken`
  (`audit_chain.token_is_live` call, `view_commit.py:703`) — a token is only valid while the
  `view_transaction` context manager that minted it still holds the lock
  (`audit_chain.py:61-68`, `:141-148`); a token held past its `with` block or
  constructed directly fails the check.
- Every canonical write is staged to `<artifact>.tmp.<version_id>` with
  `O_CREAT|O_EXCL|O_WRONLY` at `0600`, fsynced, then renamed; the directory
  entry is fsynced after the rename batch and again after any remove, before
  the witnessing audit row is appended (`_stage_and_rename`, `:637`;
  `commit_view_locked`, `:688`).
- Hostile-YAML refusals added this pass, all in `view_commit.py`: merge keys
  (`<<`) are refused in the parser itself via a `SafeLoader` subclass
  (`_ViewLoader.flatten_mapping`, `:90-96`), base-60 (sexagesimal) numeric
  scalars are refused under every YAML 1.1 int/float tag spelling
  (`_refuse_base_60`, `:105-119`), and a parsed document is walked to reject
  self-referential aliases, nesting past 64 levels, or expansion past 200,000
  visited nodes (`_check_bounded`, `:126-149`) — all three defend the view
  lock's hold time against a hand-edited or maliciously-expanded
  `view.yaml`/plan.
- A `--re-pair` row is bound to the view actually on disk: its `view_hash`,
  `view_id`, and `version_id` are recomputed from the live `view.yaml` and
  compared against the row, never trusted from the row or from a stale
  `metadata.view_hash` field (`_validate_re_pair_against_disk`, `:507`,
  with explicit `# SECURITY:` comments at `:383` and `:397` on why the
  stored hash is never trusted).
- `audit_chain.append_entry` uses a race-free `O_CREAT|O_RDWR` open (never
  truncates), re-asserts `0600` on every append, and fsyncs the row
  (`audit_chain.py:303-382`) — unchanged this pass, re-read to confirm it
  still underlies the hardened writer above.

**`audit_append.py` / command-injection avoidance (`bae0c6c`, #159).** The
documented operator command never carries the audit row as a shell argument:
the row is written to a draft file and the helper reads it via
`render_gate.read_draft` (extended this pass to accept a `.json` suffix
alongside the existing `.md` report-draft form — same descriptor-based,
symlink-refusing reader, `render_gate.read_draft`, `render_gate.py:222`, unchanged in substance).
`tests/test_audit_append.py::test_documented_command_runs_in_bash_with_hostile_text`
runs the loader's documented one-line command verbatim with a row field
containing `$(touch PWNED)`, backticks, and a brace-JSON fragment, and asserts
the file is never created and the command still succeeds — a positive proof
the literal-draft-file pattern defeats shell injection through row content.

**Client-policy helper input guards
(`client-policy/adaptation.py:1494`, `client-policy/reconcile.py:553`, `_parallax/coverage_check.py:338`,
each a `_read_input_file`).** Companion to the `8d53109` change that routes
client-policy payloads through literal draft files the same way `bae0c6c` did
for house-view. Each of the three modules carries its own (not shared-import)
copy of the guard: for a path whose parent directory is literally named
`.parallax-policy`, the parent must not itself be a symlink, the file is
opened with `O_NOFOLLOW` and `O_NONBLOCK` (refusing a FIFO hang), must be a
regular file (`stat.S_ISREG`), and must carry exactly one hard link
(`st_nlink == 1`) before its bytes are read and UTF-8-decoded. Same
descriptor-after-check discipline as `view_commit._read_staged_file`, applied
independently in three files. See Critical Findings Detail for one
non-blocking gap versus that same sibling function.

**Conventions §10.3/§14.4 (#168).** The documented draft path for the
render gate and the client-policy helpers may now be relative to the
working directory as well as absolute; `~`, `$VAR` and `${…}` stay
forbidden, so the command remains shell-literal. No reader changed:
`render_gate.read_draft` still resolves the path with `os.path.abspath`
and applies the same basename-only containment check (Critical Findings
Detail item 1), and the three `_read_input_file` guards are unchanged.
A relative path therefore resolves against the helper process's cwd,
which is the session cwd the documented command runs in. §14.4 also adds a
rule that `.parallax-policy/` holds only payload drafts and its
`.gitignore`, and that the model must never write or run its own code in
place of a documented helper or the render gate. That rule is instruction
text; the eval checker's new model-written-code failure is the test that
watches it.

**Literal policy draft paths (`.parallax-policy/`).** `.gitignore:93` adds
`.parallax-policy/` (confirmed present, mirrors the pre-existing
`.parallax-render/` entry at `.gitignore:92`); conventions §14.4 documents
writing each payload to `<cwd>/.parallax-policy/<label>-<8 hex>.<ext>` via
write-artifact and passing that literal path to the helper's flag, replacing
an `mktemp`+shell-variable form that Claude Code's own permission checker was
silently refusing (per the `8d53109` commit message) — a reliability fix
with a security side effect: shell-variable interpolation of policy content
is removed from the documented command surface entirely.

**`DECISIONS.md` untracked (`1e97b6b`, #165).** The file (1129 lines) is
removed from the tracked tree and added to `.gitignore:57`; `CONTRIBUTING.md`,
`CHANGELOG.md`, and `.github/dependabot.yml` updated to stop pointing
contributors at it. Reduces public-repo surface for internal
decision-rationale content; `git log --all --full-history --diff-filter=A --
DECISIONS.md` still finds it in history prior to this commit (expected — this
is a stop-tracking change, not a history rewrite, and history rewrites are
out of scope for a routine audit).

**Eval harness (`evals/concierge_journeys_check.py`, +215 lines across the
three touching commits).** Test infrastructure, not production attack
surface, but directly relevant to SEC-04/SEC-12 verification rigor: the
checker now (a) recognizes `adaptation.py`/`coverage_check.py`/`reconcile.py`
invocations as documented helper commands on the same footing as
`render_gate.py`/`audit_append.py`, (b) classifies a permission denial on one
of those commands as blocking rather than a warning
(`classify_denials`, confirms the documented command actually ran, not just
that the model said it would), and (c) added in `bb30742`: fails a journey
outright if the model wrote and ran its own ad hoc script instead of a
documented helper. (c) is a meaningful regression guard — it is exactly the
class of silent substitution (an improvised unaudited write path standing in
for the hardened one) that would otherwise let a future change quietly
bypass the guards described above without any test turning red.

   `write-artifact` host tool's actual output mode for a draft remains

3. **(Low, RESOLVED this pass) Symlink-check asymmetry in `verify_release()`.**
   The 2026-10-11 audit recorded that `index.json` (`release.py:308`,
   `.read_text()`) and `SHA256SUMS` (`release.py:332`, `.read_text()`) were

   network boundary.
