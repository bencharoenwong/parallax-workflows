## Security-relevant change

**`skills/_parallax/white-label/validator.py` (`DesignMdValidator`,
commit `6eb8591`) — the task's flagged change.** Replaced an `npx -y
@google/design.md` network-fetch-and-execute call with a local-only,
checksum-verified binary:

- `_configured_cli()` requires **both** `PARALLAX_DESIGN_MD_CLI` (an absolute
  path) and `PARALLAX_DESIGN_MD_SHA256` (a `[0-9a-f]{64}` digest) as
  environment variables; either absent or malformed returns `None` and lint
  is skipped (`validator.py`, `_configured_cli`).
- The path is resolved with `strict=True`, must be a regular file
  (`is_file()`) and executable (`os.access(X_OK)`), and its SHA-256 over
  `read_bytes()` must equal the configured digest, re-verified on **every**
  call — no caching of the availability result (prior code cached `npx`
  availability for the process lifetime; this version does not cache the
  pass/fail verification).
- `subprocess.run` now invokes `[str(command), "lint", ...]` directly —
  no package manager, no `-y` auto-accept, no implicit registry resolution.
  Added `stdin=subprocess.DEVNULL` and `cwd=temp_dir`.
- Output handling tightened: the JSON result must be a `dict` with a
  `findings` list of `dict` rows or the result is `skipped`, and the old
  `note` field's `res.stdout[:100]` echo (an unbounded-content leak into a
  structured result) is gone — errors now report only `type(error).__name__`.
  This is also a minor, non-blocking improvement relevant to error-response
  hygiene norms generally, though SEC-08 stays NA for this repo (no HTTP
  surface).
- `.github/workflows/evals.yml`, `CONTRIBUTING.md`,
  `skills/_parallax/scripts/run-gate-tests.sh` were checked for a shifted (not
  removed) network fetch — e.g., CI computing the digest or installing the
  package at run time. None of the three does this: the CI comment and
  CONTRIBUTING text were updated to state "a separately installed
  executable and checksum; it does not download dependencies," and the
  `npx`-marked smoke test stays deselected by default
  (`-m "not npx"`), opt-in only via `PARALLAX_GATE_MODE=network`. The
  headline claim holds: the network fetch was removed, not relocated.
- `skills/parallax-white-label-onboard/SKILL.md` and `CHANGELOG.md` describe
  the same `PARALLAX_DESIGN_MD_CLI`/`PARALLAX_DESIGN_MD_SHA256` contract;
  docs and code agree.
- Two Low, non-blocking residual items: (a) the hash is computed via
  `read_bytes()` and the path is exec'd in a later, separate step — a
  TOCTOU swap window exists in principle, but both env vars are
  operator-set, not attacker-reachable input, so the realistic threat model
  is weak; (b) hashing the target file does not pin a shebang interpreter's
  own integrity if the configured path is a wrapper script rather than a
  compiled binary. Neither changes the verdict below.
- `diff plugin/skills/_parallax/white-label/validator.py
  skills/_parallax/white-label/validator.py` — identical.

**`skills/_parallax/white-label/loader.py` `safe_source_reference()`
(touched across several commits in this diff).** This function exists to
keep pre-signed URLs, internal paths, and credential-bearing query strings
out of client-facing report footers. Changes add: a 256-character cap on
every return path, rejection of a bare `scheme:` with no `//` authority
(previously such a string fell through to the path-basename branch, which
could echo a scheme-prefixed string without stripping it), explicit
protocol-relative (`//host`) handling, and a Windows-drive-path carve-out so
`C:\...` is treated as a local path rather than a rejected scheme. All
changes narrow what can pass through; none widen it. `visual_branding_summary()`
additionally now requires a displayable name or a nonempty color/font/logo
value before reporting `white_label_active: true`, closing a case where an
all-default config could report active branding.

**`evals/concierge_journeys.sh` (commit `1613380`/later).** Replaced
per-line `jfield`/`selected` shell parsing with a single Python
`--prepare` pass emitting NUL-delimited records consumed via
`read -r -d ''`, removing word-splitting exposure to journey prompts
containing shell metacharacters. The prepared temp file uses `mktemp` under
`$TMPDIR` with an `EXIT` trap removing it. The MCP tool-call timeout was
raised to 5 minutes (`MCP_TOOL_TIMEOUT`) alongside the existing idle-timeout
disable, both overridable by an operator-set env var, bounded by the
script's own overall journey timeout. This is owner-run eval tooling (not
CI, not shipped in `plugin/`), consistent with how prior audits scoped it.

**`skills/_parallax/coverage_check.py` (date-contract validation,
commit `fb25e7d`).** Added `_iso_snapshot_date`/`_comparable_snapshots`:
rejects mixed dated/undated sector rows, multiple dates without an explicit
`--snapshot-date`, and duplicate sector rows at the selected date —
replacing silent wrong-answer risk with a raised `CoverageInputError`. Pure
input-validation hardening on a local analysis helper; no new external
input surface.

**Grep-swept, not line-audited** (pure business-logic/doc files; no
code-execution, auth, or network-boundary surface by file type):
`pair_math.py`, `attribution.py`, `desk_call_list_logic.py`,
