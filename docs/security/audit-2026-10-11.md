## Critical Findings Detail

None at Critical or FAIL severity. Four non-blocking items carried forward
from the two prior audits, all independently re-confirmed present at HEAD
this pass (current file:line, not reused from the prior audit text):

1. **(Medium, open) Render-gate path-containment is basename-only, not
   cwd-anchored.** `render_gate.py:238` accepts any parent directory whose
   `os.path.basename()` equals `DRAFT_DIR_NAME` (`render_gate.py:219`,
   `".parallax-render"`) — it does not check that directory sits under the
   session's resolved cwd. The docstring at `render_gate.py:229` discloses
   this plainly. Exploiting it needs an already-existing file at an
   unguessable 8-hex-suffix path, so it remains non-blocking. CWE-22-adjacent
   (improper limitation of a pathname to a restricted directory).
2. **(Medium, open) Draft file mode unmeasured against the real host tool.**
   The file mode the host's `write-artifact` tool actually produces for the
   draft (vs. this shell's `644`-by-umask throwaway test file, or the prior
   `mktemp` form's `600`) has not been measured in any audit pass to date.
   Not re-tested this pass; remediation since r2 did not touch this surface.
3. **(Low, open) Symlink-check asymmetry in `verify_release()`.**
   `path.is_symlink()` is checked for every entry in `index["assets"]`
   (`release.py:316`) before hashing, but `index.json`
   (`release.py:308`, `.read_text()`) and `SHA256SUMS`
   (`release.py:332`, `.read_text()`) are read with no equivalent check.
   Only matters if `release.py verify` is ever pointed at a directory the
   caller did not just build themselves; the documented workflow
   (`docs/releases.md` § "Check and build") always verifies a just-built,
   trusted staging directory. CWE-61-adjacent.
4. **(Low, open) Unbounded read in `digest()` for non-archive files.**
   `digest()` (`release.py:49`) reads an entire file into memory before
   hashing; `index.json`/`SHA256SUMS` are not subject to `unpack()`'s
   5,000-member/200 MB pre-check the way `.zip`/`.skill` assets are. Same
   attacker-model caveat as item 3 — local self-verification, not a network
   boundary.

None of the four change the SEC-04/SEC-10/SEC-12 PASS verdicts above (none
rises to Critical, and none is newly introduced by the combined-tree
interaction reviewed in the Scope Note). All four are recorded for the
maintainer's backlog.
