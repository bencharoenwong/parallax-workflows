**What changed since the prior audit's commit.** The prior audit reviewed the
branch at a point with zero commits beyond `origin/main` — a stdin-heredoc-only
form. Since then, four commits landed
(`2fbbd16`, `ad59c80`, `fce8efc`, `408b2cb`, confirmed via
`git log origin/main..HEAD`) that are exactly that stdin-heredoc change plus a
regression test and changelog/decision-log entries. **On top of those commits,
the working tree now carries a second, uncommitted change**: `skills/_parallax/render_gate.py`
gained an `--input PATH` flag and a `read_draft()` function, and all 22 gated
`skills/parallax-*/SKILL.md` files plus `skills/_parallax/parallax-conventions.md`
§10.3 (and their `plugin/` mirrors — confirmed byte-identical to source via
direct `diff`, including the §10.3 section specifically, verified line-for-line
after the plugin bundle's unrelated pre-existing drift on an unrelated
translate-language row was ruled out as out of scope) were rewritten to tell
the model to `write-artifact` the drafted report to
`<cwd>/.parallax-render/<skill-key>-<8 random hex>.md` and run the gate with
`--input <path>` instead of a stdin heredoc. This audit covers **both** layers
(the four committed commits and the uncommitted `--input`/`read_draft` delta
on top), since both will be included if this branch is pushed as-is.

**`read_draft()`, what it does (current state, after remediation):** given
`--input PATH`, it accepts only a path whose immediate parent directory is
named `.parallax-render` and whose filename matches `<skill>-<8 lowercase
hex>.md` for the skill being gated — any other shape is refused before the
path is opened (`ValueError`, exit 2, nothing printed, nothing deleted). On a
path that matches, it opens the containing directory and then the file
relative to that directory using `O_NOFOLLOW` (and `O_DIRECTORY`/dir_fd where
the platform supports it; a path-based `os.path.islink` pre-check on
platforms without dir_fd support, e.g. Windows), opens with `O_NONBLOCK` so a
FIFO cannot hang the gate and `O_BINARY` where that flag exists (Windows),
requires the open file to be a regular file with exactly one hard link
(`stat.S_ISREG` and `st_nlink == 1` — new this pass), reads it, deletes it,
and removes the now-empty `.parallax-render` directory. A failed unlink is a
stderr warning, not an error — the report still renders. Non-UTF-8 content
fails closed (`UnicodeDecodeError` is a `ValueError` subclass) after the file
has already been unlinked. Output now goes to `sys.stdout.buffer` as
explicit UTF-8 bytes rather than `sys.stdout.write()`, so a non-UTF-8 locale
cannot raise after the draft is already gone — new this pass.

## Remediation applied since the first pass of this file

The coordinator reported, and I independently verified, four changes landed
in the working tree since this audit's first pass:

1. **`.gitignore` now excludes `.parallax-render/`.** Verified directly:
   created a real `.parallax-render/<skill>-<8hex>.md` test file in the
   worktree and ran `git check-ignore -v` against it — matched
   `.gitignore:90:.parallax-render/`, confirming the rule is live and
   correctly shaped (leading dot, trailing slash), not just present as text.
   Removed the test file and directory afterward; `git status` shows no
   trace. This closes the SEC-10 finding from this audit's first pass (the
   finding text is retained below, marked RESOLVED, for the audit trail).
2. **`read_draft()`'s docstring no longer overclaims.** It now reads "Any
   directory of that name qualifies; the gate does not check that it sits
   under the session's cwd" (`render_gate.py`, `read_draft()` docstring) —
   this is an accurate disclosure of the containment gap this audit's first
   pass flagged (the code behavior is unchanged; only the documentation's
   claim about it changed, from overclaiming to stating the real
   constraint). I re-read the function: the behavior matches this corrected
   description, not the old one. Logged below as still-open but now
   honestly documented (SEC-04 evidence).
3. **Hardlink defense added.** `read_draft()` now rejects a draft whose
   `st_nlink != 1` with `ValueError("draft has other hard links: ...")`,
   verified via the new `test_input_refuses_hard_linked_draft` test (creates
   a real hardlink with `os.link()`, confirms rejection and that the
   original file survives) and by reading the code: the check runs on the
   already-`O_NOFOLLOW`-opened file descriptor, after the regular-file
   check, before any read. This is a stronger defense than this audit's
   first pass asked for (I had scored the hardlink question as "considered,
   not a new escalation" because exploiting it needs access to the source
   file; the new check closes it outright rather than merely leaving it
   theoretically safe).
4. **UTF-8-safe output and §10.3 risk disclosure.** `main()` now writes to
   `sys.stdout.buffer` as encoded UTF-8 instead of `sys.stdout.write()`,
   avoiding a `UnicodeEncodeError` under a non-UTF-8 locale after the draft
   is already deleted (confirmed by reading the new code and the new
   `test_input_output_is_utf8_whatever_the_locale` test, which writes a
   draft containing non-ASCII characters and asserts the subprocess exits
   0). `parallax-conventions.md` §10.3 now states plainly: "If the working
   directory is synced (Dropbox, iCloud) or a git work tree, the draft can
   be uploaded or committed in that window... The draft holds the full
   report, client data included, until the gate deletes it," and a second
   gate failure now writes `Render gate: not applied (gate error)` into
   About This Report instead of leaving that failure mode undocumented.

### Finding (RESOLVED this pass): Render-gate draft directory was not gitignored in a public repo

**Severity**: was High (scored as a FAIL on SEC-10 at this audit's first
pass, in the critical set, blocking the push gate)
**Status**: RESOLVED — `.gitignore` now carries a `.parallax-render/` entry;
verified live with `git check-ignore -v`, not just by reading the diff.
**Location**: `.gitignore` (repo root, line 90 as of this pass); draft path
defined at `skills/_parallax/render_gate.py` `DRAFT_DIR_NAME = ".parallax-render"`;
convention documented at `skills/_parallax/parallax-conventions.md` §10.3
**CWE**: CWE-312 (Cleartext Storage of Sensitive Information) /
CWE-532-adjacent (sensitive artifact left trackable in a VCS working tree)

### Description (as originally found, retained for the audit trail)
The render-gate draft (the complete, unredacted report text — which per this
skill family's documented purpose can include client holdings and portfolio
detail) was written to a predictable directory name (`.parallax-render/`)
inside the session's working directory, with a random-but-discoverable
filename, and that directory name was absent from `.gitignore`. Under a
clean run the gate deletes both the file and the directory; under an
interrupted run the file would have survived at a path git considered
ordinary and stageable.

### Remediation applied
Added `.parallax-render/` to `.gitignore` (one line, with an explanatory
comment noting it may hold client data). This was the only change needed to
close the actual git-trackability vector; it does not change `read_draft()`
or any other code path, so it carries no interaction risk with the
concurrently-reviewed `render_gate.py`.

### Residual items (not re-opened as FAILs, tracked for follow-up)
- File mode on the draft as actually written by the host's `write-artifact`
  tool is still unverified (this repo's shell umask produces `644`; the real
  host tool's behavior was not measured in either pass).
- `read_draft()`'s path-containment check still accepts any directory named
  `.parallax-render`, not only one rooted at the session's cwd — now
  correctly documented as a known limitation rather than a false guarantee,
  but the limitation itself is unchanged.
